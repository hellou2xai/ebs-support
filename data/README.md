# Data dictionary: Vertiv Oracle EBS AMS agentic app demo ("Alice")

All files are synthetic except `incidents_real.csv` and the 20 `DATA_ORIGIN=REAL`
rows inside `incidents.csv`, which are the actual ServiceNow incidents from the
high-impact dump. Everything is regenerated by `../generate_synthetic_data.py`
(deterministic, fixed seed). Naming follows Oracle EBS R12 conventions.

## The real landscape (from the dump)

Program codename **Alice**. Support is organised by value stream, read from the
real assignment groups:

- **Item-MDM** (`Oracle-Alice-Item-MDM`): PD / Agile PLM to EBS item and revision
  sync. Change orders CO / CCO / NRCO / ECO, CCB reports, Item Workbench. Biggest
  cluster.
- **QTD** Quote-to-Delivery (`*-QTD`, `OMCS-ERP-Alice-QTD`): order holds, CPQ
  submission, plant/warehouse, DropShip.
- **PTM** Plan-to-Manufacture (`*-PTM`, `*-OSA-PTM`): planning/pegging, receiving
  (RCV_INTERFACE), BluJay transmission, APPTREE_EVENT.
- **PTC** Plan-to-Cash (`*-PTC`): revenue recognition / obligations.
- **Services** (`*-Services`): service contracts.

Systems: **AGILE_PD, ITEM_MDM, EBS, CPQ, BLUJAY, CLOUD2EBS_DROPSHIP.**

Key signal: tickets recur and get recreated (linked incident references in the
data). `RECURRING_FLAG=Y` marks them. That is the case for "resolve at source".

## Knowledge graph traversal

The graph supports the two demo questions:

- "Fix this ticket": `Incident -MATCHES_PATTERN-> IssuePattern -> KnownAction/DataFix`.
- "Fix it at source": `Incident -CAUSED_BY-> RootCause -RESOLVED_AT_SOURCE_BY-> PermanentFix -TARGETS_SOURCE-> System`,
  plus `Incident -RECURRENCE_OF-> Incident` to show how often the same root cause
  has come back.
